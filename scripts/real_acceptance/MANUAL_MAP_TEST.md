# 手动建图与原生 AMCL 定位

## 1. 建图并保存

使用原遥控器低速建图。静止后保存地图，保留同一地图中的目标坐标。

```bash
bash scripts/real_acceptance/run_map_test.sh map
```

地图完整且车辆停稳后，在另一终端保存：

```bash
bash scripts/real_acceptance/run_map_test.sh save
```

保存成功后结束 map 终端。已有地图保留原文件；新地图通过 `--map` 指定新路径。

## 2. 原生全局定位

```bash
bash scripts/real_acceptance/run_map_test.sh localize
```

启动 map_server、AMCL、Point-LIO 及现有扫描转换链。定位程序等待输入与 AMCL
active 后调用 `reinitialize_global_localization`，由 AMCL 在空闲区域初始化粒子。
响应后等待新位姿；静止更新调用 `request_nomotion_update`。云台和底盘保持静止。
重新摆放车辆后结束本次 localize，再重新启动。

JSON `latest.candidate_stable` 和 `/acceptance/localization_ready` 表示以下数据检查
连续满足 3 秒：定位与扫描时间差至多 0.025 秒、消息和 TF 年龄至多 0.75 秒、
位置方差小于 0.04 m²、朝向方差小于 0.025 rad²。位姿与扫描须包含有效数值。
位置和朝向正确性由现场另行复核；对称场地需要特别确认。

日志保存在 `results/localize_时间/`。重新定位时调用原生接口，人工初始位姿保持空缺。
雷达标定候选通过 `SENTRY_ACCEPTANCE_LIDAR_CALIBRATION` 显式选用。

## 3. 选点并执行低速导航

RViz 顶部 **2D Goal Pose** 保存目标。保持 localize 终端运行，确认地图位置、
朝向及目标，现场准备遥控接管并打开既有导航使能后，显式执行：

```bash
bash scripts/real_acceptance/run_map_test.sh drive --execute --face-motion
```

默认平移上限 0.15 m/s。既有速度限制、遥控接管、停车、障碍检查和云台跟随继续沿用。
先验证单独对准时使用 `drive --execute --face-motion --align-only`。

## 4. 验收顺序及记录

保留同一地图及目标（重复测试无需重新点选），逐组测试并记录真实摆放：

| 组别 | 起点 | 车体相对首次朝向 | 云台相对车体朝向 |
|---|---|---|---|
| A | 位置 1 | 0° | 0° |
| B | 位置 1 | 90° | -90° |
| C | 位置 2 | 180° | 45° |
| D | 位置 2 | -90° | 180° |
| E | 位置 3 | 任意角度 | 另一任意角度 |

角度用于记录测试覆盖，不作为人工初始位姿输入。每组需验证：不扫描即可
正确定位、实际运动方向正确、抵达同一真实目标、停稳。终点定位误差应
≤0.06 米，并通过地面标记/尺测独立复核，不能仅看定位器自己的误差。

先完成无新增障碍路线，再停稳放置一个地图中没有的箱子，留出绕行空间，
观察红色扫描点/代价地图/新路径及实际绕行。随后再单独做受控的运动中障碍
变化测试和通道完全阻断停车测试；不让人员充当障碍。遥控接管后必须人工
确认并重新发起 drive，不自动恢复。每组报告在 `results/stationary_goal_时间/`。

### 2026-09-17 静止定位修复

首次随机全局 AMCL 收敛到错误位置，现场已否决；低协方差、粒子集中不能
单独证明正确。全图几何搜索在相同静止数据上找到另一端的更优位姿，独立
采样复核匹配约 95%–97%；自动初始化后 AMCL 实时指标持续通过。证据在
`results/stationary_diagnosis/`、`results/stationary_seed_trial/`。尚需现场核对，
不得据此宣称所有起点已通过。合成测试覆盖不同位置/朝向及对称场景拒绝：

```bash
python3 scripts/real_acceptance/test_localization_pair.py
```

本方案使用本地图的有限网格搜索，候选差值为拒绝歧义的经验指标，不是
绝对唯一性的数学证明；场景缺乏特征时依然会停在原地。

### 1.0 m/s 提速验收（尚未通过）

`map_test.py drive --max-speed 1.0` 可显式选择最高平移指令，默认仍为
0.15 m/s。高于默认速度只支持已保存目标且启用运动方向跟随的验收流程。
这只作用于验收桥接器，尚未接入 `scripts/run_competition.sh`。

桥接器按平移向量模长限速，升速限制为 0.30 m/s²，接近目标时减速；
零指令立即发送。按现场要求已移除额外的 2.5 米直线走廊检查及其
0.30 m/s 降速限制，采用 Nav2 原有障碍层、膨胀层、路径碰撞检查和
实时重规划。保留原有短时保存地图边界检查、近距离净空和数据有效性
检查。此修改不代表高速动态避障已验收。

本轮结果：

- 0.30 m/s 指令停车试验：定位估计发零后最大位移约 0.063 米，轮速反馈
  约 0.47 秒降到接近零。原始证据 `results/speed_acceptance/brake_030/`。
- 1.0 m/s 上限试验：最高实际发送指令约 0.411 m/s，遥控手动接管后
  中止，最终四轮反馈为零。证据 `results/speed_acceptance/brake_100/`。
  未达到 1.0 m/s，不能验证该速度的制动、绕障或完整航点导航。
- 1 米行程上限仅用于短距离试探；按 0.30 m/s² 从静止升至 1.0 m/s，
  理想条件下仅加速就需要约 1.67 米，尚不含停车距离。因此后续满速试验
  必须结合实际可用路线安排，不能凭短距离试验判定满速通过。

现有 PB 控制器的动态参数回调未同步重建内部 PID，因此不能仅凭运行时
参数读回值确认原生控制器已限速；本轮限速由验收桥接器执行。
急停、遥控及 Hub 仲裁未修改。遥控接管后不自动重试。

离线验证：`python3 -s scripts/real_acceptance/test_speed_profile.py`。

本轮停止原因更正：现场确认没有遥控接管。旧脚本将原始遥控离线和通道超过
中位阈值统一报告为 `RC manual takeover`，因此上文“遥控手动接管”只代表
旧错误字符串，不能认定人为操作。触发瞬间未记录通道值，历史根因尚未确定。
后续静态采样 25198 帧原始遥控数据均在线、五个通道均为零，未复现异常。
现在分别报告离线、授权失效、无效通道及通道偏移，并保存触发快照和最近
100 条异常原始帧。停车阈值仍为 0.05，急停、遥控和仲裁代码未修改。
