## 隔离启动静态验收（已实现）

```bash
bash /home/soyo/sentry_ws/scripts/real_acceptance/run_static.sh
```

约 40–60 秒后自动结束，只停止本次启动的进程。报告在
`/tmp/sentry-static-acceptance/report.json`，运行日志在同目录的 `launch.log`。
退出码 1 表示有验收项未通过，不代表脚本执行失败。

- 静态启动使用独立 ROS 域 88、仅本机通信；实车控制域为 0。静态工具不跨域发送速度。
  显式运行动态验收时，受遥控、传感器和距离门控的测试程序才向原 Hub 发布速度。
- 最终速度重定向到 `/static_acceptance/cmd_vel`，初始小陀螺速度置零。
- 不启动比赛控制器、手柄、Hub、电机、发射及默认关节状态发布器。
- 只启动真实雷达、Point-LIO、机器人固定安装 TF 和导航算法。
- `yaw_feedback.py` 只读域 0 的真实 LK yaw 编码器，单向向域 88 发布关节状态；
  实车域不创建控制发布者。在线位、消息时间和接收时效均检查，断流后停止发布。
  角度沿用现有 Hub 的编码器零位及变换约定，物理正负方向仍需低速验收。
- 验收专用 URDF 将原模型的两个虚拟 yaw 级合并成一个实际关节，保留安装平移。
  原模型和遥控器配置不变；不补造第二份编码器角度。
- 使用局部在线地图诊断；SLAM 每 0.05 秒发布估计的 `map -> odom`，不再使用静态零变换。
  预建地图定位必然标为未验收，不保存或覆盖实车地图。
- 若已有本机雷达/Point-LIO 进程，或域 88 已占用，拒绝启动，避免争抢传感器。
  已运行比赛导航时只能使用下文的只读工具，不能重复启动雷达。

## 已运行系统的只读观察

当前工具只做只读预检，可以在比赛进程运行时旁路执行。不发布运动、云台、
裁判或遥控指令，不修改参数，不调用导航动作，不接管急停。
它不是运动门控，不能根据这个报告自动放行比赛导航。

```bash
cd /home/soyo/sentry_ws
source install/setup.bash
python3 scripts/real_acceptance/check.py
```

默认观察 10 秒，报告 `/tmp/sentry-real-acceptance.json`。使用实车原有 ROS 环境，
不要套用仿真的 ROS_DOMAIN_ID=87。退出码 1 表示存在静态检查失败。
所有静态项通过也不代表动态验收通过；报告始终保持
`physical_acceptance_passed=false` 和 `motion_authorized=false`。
TF 项只检查连通，不证明新鲜度、发布者唯一性或轴向正确。

## 现场验收顺序

1. 先确认遥控急停和断联保护有效；由现场人员操作遥控器，观察真实执行器停止。
   不修改遥控开关、解释器、Hub 仲裁或底盘急停路径，不用软件伪造遥控输入。
2. 在当前空旷测试区域建图，保存可辨认的地图目标；不需要比赛场地。
   没有该区域地图和可信定位时，不执行地图目标导航。
3. 低速验证底盘前、左、正旋转，再在不同云台角度下复验。
   初始建议上限 0.15 m/s，须先确认底盘实际单位和限制生效。
4. 四种初始朝向分别运行自动定位、实际启动动作和同一命名目标。
   不注入初始位姿；外部标记或视频测量终点，不仅看定位器自己的到达结果。
5. 验证静态及移动障碍、定位中断和指令中断。记录实际停车时间与距离。
   每一阶段失败都停止进入下一阶段；急停随时优先。

启动动作授权和导航授权分开；检查未完成则不放行导航，不可超时强行放行。

修改前后保留控制器源码及配置指纹。指纹不变仅证明文件未变化，不能证明
实车急停性能，也不能证明运行二进制与源码一致。
